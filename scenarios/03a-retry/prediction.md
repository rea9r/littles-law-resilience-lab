# 03a リトライを入れる

01b（タイムアウト 300ms、決済 API はトランザクションの外）に、Resilience4j の Retry を足す。最大 3 回試行、試行の間に 500ms 待つ（どちらも Retry の既定値）。

## 予測

- 1 リクエストの W は最大 3 × 0.3 + 2 × 0.5 = 1.9 秒。試行の間の待ち時間もスレッドを握ったまま
- 障害中の L は 60 × 1.9 = 114 で上限 40 を超え、約 0.7 秒でスレッドが尽きる。01b では安全だった 300ms が、リトライによって安全でなくなる
- 決済 API に届く呼び出しは最大で 3 倍になる
- /products も巻き込まれ、再起動も起こりうる

## 合格条件

- 障害開始から 2 秒以内にスレッドが上限に達する
- 障害中の /products の成功率が 50% 未満
