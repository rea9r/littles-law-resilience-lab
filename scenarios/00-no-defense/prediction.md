# 00 防御なし

決済 API のタイムアウト 30 秒、決済 API はトランザクションの中で呼ぶ、HikariCP の取得待ちは既定の 30 秒。

## 予測

- 決済 API を待つ間もコネクションを握るので、必要なコネクション数は 60 rps × 5 秒 = 300。プールの 10 は 10 ÷ 60 ≈ 0.2 秒で尽きる
- その後の /orders はコネクションを最大 30 秒待つので、スレッドも 40 ÷ 60 ≈ 0.7 秒で尽きる
- /products はスレッドもコネクションも取れず、ほぼすべて失敗する
- /livez も同じスレッドプールで受けるので応答できず、liveness probe が 3 回（約 15 秒）失敗した時点で Pod が再起動する
- スレッドは埋まっているが待っているだけなので、CPU 使用率は低いまま

## 合格条件

- 障害開始から 2 秒以内（スクレイプ間隔）にスレッドが上限に達する
- 障害中の /products の成功率が 10% 未満
- 障害中に order-api が 1 回以上再起動する
- 障害中の CPU 使用率の平均が 30% 未満
