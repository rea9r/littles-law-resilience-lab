# 03b サーキットブレーカーで λ を絞る

03a に加えて、Resilience4j の CircuitBreaker を入れる。直近 10 秒で 20 件以上呼び、半数以上が失敗したら open にする。open の間は呼び出しをすぐに断り、5 秒後に半開状態で 10 件だけ試す。

## 予測

- open になるには、失敗した呼び出しが 20 件たまる必要がある。最初の失敗が返るのはタイムアウトの 0.3 秒後なので、open になるのは障害開始から 0.6〜0.7 秒後
- それまでに届いたリクエストは、1 回目の失敗のあとリトライの待ち（500ms）に入り、スレッドを握ったままになる。0.7 秒 × 60 rps ≈ 40 件がそれぞれ 0.8 秒ほどスレッドを握るので、障害の直後に一瞬だけスレッドが上限に届きうる（1 回目の実行で観測した）
- open になってからは、決済 API への呼び出しをすぐに断る（断った呼び出しはリトライしない）。W はほぼ 0 になり、スレッドが空く。決済 API への λ もほぼ 0 になる
- スレッドが埋まるのは数秒だけで、その間に届いた /products も Tomcat の待ち行列で数秒待てば処理されるので、k6 のタイムアウト（5 秒）には掛からない
- 遅延を外すと、次の半開状態（5 秒以内）で試した呼び出しが成功し、閉じて元に戻る

## 合格条件

- 障害中の /products の成功率が 95% 以上
- 障害中に決済 API が受ける呼び出しが 01b（約 60 件/秒）より大幅に少ない
- 再起動 0 回、回復まで 15 秒以内
