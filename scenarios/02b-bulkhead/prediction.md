# 02b バルクヘッドで L を区切る

02a に加えて、決済 API の呼び出しを Resilience4j の Bulkhead で同時 12 件までに制限する（空きがなければ待たずに断る）。

## 予測

- 平常時の 決済 API の呼び出しの L は 60 × 0.1 = 6。枠 12 は平均の 2 倍
- 障害中、決済 API の呼び出しが使えるスレッドは最大 12。12 ÷ 0.8 = 15 件/秒が 決済 API まで届いてタイムアウトし、残りの約 45 件/秒はすぐに 503 で断られる
- スレッドの L は 12 + α で上限 40 に収まり、/products は守られる
- 到着がランダム（ポアソン分布）なら、平常時にも同時呼び出しが 12 を超えた分（約 2%）は断られるはず。ただし k6 の constant-arrival-rate は等間隔に送るので、この環境ではほとんど起きない（実測は 0 件）

## 合格条件

- 障害中のスレッドの最大値が 30 未満
- 障害中の /products の成功率が 99% 以上
- 再起動 0 回
- 平常時にバルクヘッドが断った件数を記録する（枠を平均の 2 倍にしたときの代償）
